# Chrome on Windows: enable Ifverse

No local install is needed. Complete [the detailed hosted setup](CHATGPT_PUBLISHING.md) once. Deployment and Sites access are not yet verified; do not enter secrets in chat.

1. **Backend:** on an authorized container host, connect the private repo and branch `codex/ifverse-chatgpt-publishing`; select `deploy/Dockerfile.publishing`, persistent `/state`, HTTPS, one instance. Enter API/OAuth secrets in the host's **Environment/Secrets** settings. Disable request/query logging. [Detailed deployment and variables](CHATGPT_PUBLISHING.md#chrome-checklist-one-time-backend-and-plugin-enablement).
2. **ChatGPT:** open [ChatGPT](https://chatgpt.com/) → **Sites → Plugin Creator**, if available. Register `sites/server.mjs` as an **owner-only** server-runtime MCP plugin at `/mcp`. Enter backend and ingress credentials directly in Sites settings and configure authenticated MCP requests. Enable it in a new chat. The exact Sites integration/UI and personal entitlement must be confirmed against the [current official guide](https://learn.chatgpt.com/docs/extend/mcp#use-a-sites-hosted-mcp-server-in-chatgpt); those pages were blocked from this workspace. Do not replace authentication with anonymous access.
3. **Google:** [Cloud Console](https://console.cloud.google.com/apis/credentials) → enable **YouTube Data API v3** → **Google Auth Platform → Clients → Create client → Web application** → add `https://YOUR-BACKEND/oauth/callback`. Configure audience/scopes and put client credentials in backend settings. Say “Connect YouTube ifverse-anime”, open the consent link, select the intended channel and approve. Ask to verify `@ifverse_anime` / `UCpB_wi5MlernpSJxUf7zWcw`.
4. **Meta:** [Business Suite](https://business.facebook.com/) → **Settings → Accounts** → confirm the intended Page and linked professional Instagram account. [Developer app](https://developers.facebook.com/apps/) → **Facebook Login [for Business] → Settings → Valid OAuth Redirect URIs** → add the callback. Configure required permissions/review; enter app credentials only in backend settings. Register exact provider IDs in the repo registry. Say “Connect Instagram ALIAS” and “Connect Facebook ALIAS”; approve each consent link and verify each separately.
5. **TikTok:** [developer portal](https://developers.tiktok.com/) → configure eligible Display API consent/owner verification if available. Register the verified OAuth ID/handle, then connect/verify it. Publishing uses [TikTok Studio](https://www.tiktok.com/tiktokstudio/upload): confirm the shown target, download the reviewed video, **Upload → Select video**, paste the exact caption, review and **Post** yourself. Return the resulting ID for independent ownership verification. Until then the result is **action required**, not published. Without eligible ownership verification access, this remains blocked/unverified.
6. **Use it:** request a prepared media job/post and platform captions → retrieve the draft ID in a fresh chat → inspect exact accounts, media and captions → say “Post it” for that clear draft, or “Post it on Instagram only”. Only the selected aliases are approved. A retry must name only the failed destination. Expect confirmed status/URLs separately for each platform.

Provider app reviews, consent, host configuration, backup restore and a verified Sites runtime remain owner setup tasks. Current rendered topics retain their pending source/editorial decisions; tests do not approve them for publication.
